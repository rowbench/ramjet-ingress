Readiness is not "the process started" — /readyz stays 503 until a route table
has been compiled from the API server, so the first Ready is the moment this
replica can actually serve. Follow it with:

    kubectl -n {{ .Release.Namespace }} rollout status {{ .Values.kind | lower }}/{{ include "ramjet-ingress.fullname" . }}
{{ if and (eq .Values.kind "DaemonSet") .Values.controller.updateStatus }}
Note — this is a DaemonSet with status writeback on, so every node runs its own
status writer. They agree (same address, same field manager), but they each
patch every managed Ingress on their own debounce, so the API traffic is nodes
times Ingresses. Set controller.updateStatus=false if that is the wrong trade.
{{ end }}
{{- if .Values.proxyProtocol.enabled }}
PROXY protocol is on for :{{ .Values.ports.http }}{{ if .Values.ports.https }} and :{{ .Values.ports.https }}{{ end }}. Those ports now *require* the header —
a connection that reaches them without going through the load balancer is
rejected, which includes anything inside the cluster dialing the Service or the
pod directly. The admin port is unaffected, which is why the probes still work.
{{ end }}
{{- if not .Values.ports.https }}
There is no TLS listener: ports.https is 0 and the daemon was given --no-https.
Whatever terminates TLS in front of this forwards plaintext to :{{ .Values.ports.http }}, so the
backend sees scheme http and X-Forwarded-Proto says http — the hop that knew
otherwise did not tell us.
{{ end }}

{{ if .Values.adminService.enabled -}}
Metrics and probes are on a separate ClusterIP Service, never on the
internet-facing one:

    kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "ramjet-ingress.fullname" . }}-admin {{ .Values.adminService.port }}
    curl localhost:{{ .Values.adminService.port }}/metrics
{{ end }}
{{- if eq (toString .Values.service.type) "LoadBalancer" }}
The traffic Service is a LoadBalancer. Until it has an address, Ingress status
{{ if .Values.controller.publishAddress -}}
falls back to the configured {{ .Values.controller.publishAddress }}.
{{- else -}}
stays empty — set controller.publishAddress if this cluster has no load
balancer controller.
{{- end }}

    kubectl -n {{ .Release.Namespace }} get svc {{ include "ramjet-ingress.fullname" . }}
{{- end }}
{{- if eq (toString .Values.service.type) "NodePort" }}
The traffic Service is a NodePort: reach it at any node's address on
:{{ .Values.service.http.nodePort | default "<allocated>" }} (http){{ if .Values.ports.https }} and :{{ .Values.service.https.nodePort | default "<allocated>" }} (https){{ end }}. NodePort Services get no
.status.loadBalancer, so Ingress status comes from controller.publishAddress or
stays empty.
{{- end }}
{{- if .Values.hostNetwork }}

The listeners are on the host network, so traffic does not go through a Service
at all: any node's address on :{{ .Values.ports.http }}{{ if .Values.ports.https }} and :{{ .Values.ports.https }}{{ end }} reaches this directly, and
the client's own address is on the socket. Point a DNS record at the nodes.

The admin port ({{ .Values.ports.admin }}) is on every node's interfaces too. It carries /metrics
and the probes, and a NetworkPolicy cannot restrict it here — policy does not
apply to a host-network pod. The node firewall and controller.adminToken are
what is left.
{{- if and .Values.controller.updateStatus (ne (toString .Values.service.type) "LoadBalancer") (not .Values.controller.publishAddress) }}

There is no address for Ingress status to read: the Service is a {{ .Values.service.type }} and
traffic does not arrive through it. Set controller.publishAddress to the VIP,
the DNS name, or whatever fronts the nodes, or the ADDRESS column stays empty.
Routing is unaffected either way — that field is advertising, not configuration.
{{- end }}
{{- end }}
{{- if lt (int .Values.ports.http) 1024 }}

:{{ .Values.ports.http }} is a privileged port, and binding it as uid 65532 works because the image's
binary carries a `cap_net_bind_service` file capability and
securityContext.capabilities keeps that capability in the container's bounding
set. Nothing else is relaxed: allowPrivilegeEscalation is still false and every
other capability is still dropped.

If the pods crash-loop with "Permission denied", the log names the port and the
remedies — the usual cause is an image built before the capability was added:

    kubectl -n {{ .Release.Namespace }} logs {{ .Values.kind | lower }}/{{ include "ramjet-ingress.fullname" . }}
{{- end }}
{{- if and .Values.hostNetwork (ne .Values.kind "DaemonSet") }}

Warning: hostNetwork is on but this is a {{ .Values.kind }}. The listeners bind
the node's ports directly, so a second pod scheduled onto the same node cannot
start. Use kind=DaemonSet, which gives exactly one per node.
{{- end }}
